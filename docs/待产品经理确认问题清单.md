## 四、步骤 5 / 6（控制测试与差距分析）

### Q11. Control Testing（控制测试）页面是否还需要？

| 项 | 内容 |
|----|------|
| **现象** | 业务流程文档把控制测试列为步骤 5；控制表页上也有「Control testing」入口。但实际使用中，步骤 3 交证据、步骤 4 控制表、步骤 6 差距分析的链路更直观，容易让人怀疑中间是否还要单独一个控制测试页。 |
| **当前实现** | 控制测试模块已存在（可建测试项、记结果）；差距分析的 `regenerate` **依赖**控制测试里非 PASS 的结果来生成缺口。若取消该页面且不改 gap 规则，缺口自动生成能力会断。 |
| **想确认** | 1）本期产品是否仍保留独立的 **Control Testing** 页面/菜单？<br>2）若保留：它在「控制表 → 差距分析」之间的必经地位如何对外说明？<br>3）若不保留：测试动作并进控制表，还是差距分析改为不依赖测试结果（例如直接从缺材料/控制表缺口生成）？ |
| **建议选项** | A. 保留独立 Control Testing 页，作为步骤 5 正式环节<br>B. 取消独立页，把「执行检查/记结果」并进控制表<br>C. 取消独立页，差距分析改为其它数据源，不再依赖控制测试<br>D. 其它（请说明） |

## 附录：和产品对齐时建议先说清的「当前系统事实」

便于产品判断「改产品规则」还是「改实现」：

1. **买范围**：决定步骤 3「生成」能灌哪些标准条款模块。  
2. **步骤 3**：生成任务 → 交证据 → send 后 AI 给证据审阅结果（文案映射）。  
3. **步骤 4**：任务可同步控制表草稿；**不**根据附件内容自动判风险；需人工/Excel/AI 补全后定稿。  
4. **步骤 5**：控制测试模块存在；测试项目前多为手工建。  
5. **步骤 6**：手工建 gap + 按控制测试非 PASS 重新生成；**不是** AI 从步骤 3 同步。若取消控制测试页，需同步改 gap 生成规则。  
6. **菜单**：多项项目内页依赖 `projectId`；未进项目就点容易报错——偏交互/信息架构问题。
